## Remaining proof limits

- **Nonzero terminal fees reach only the public burn wallet:** the schema rejects
  `dev_wallet`, but no launch route implements a nonzero terminal fee leg. Add a
  calldata/fork assertion of the exact public burn recipient, amount and user
  payout, rejection of the dev recipient, and no Pons launch fee before enabling
  fees. The `burn_engine` schema alternative is for a later gated Drop, not the
  current launch destination (FACTS §5; BACKEND §12.3).
- **No custody across every production process:** unsigned route fixtures above
  do not prove the absence of all user signing/key-storage paths. Add a role-image
  integration check that user transaction signing/broadcast cannot be invoked
  and that only the gas-only receipts signer can sign registry commits. Confirm
  deployed secret mounts and grants separately (BACKEND §18).
- **Destruction across disaster recovery without the retained ledger:** current
  tests restore a database while retaining the destruction ledger. Add a complete
  recovery drill proving the separately backed-up ledger cannot be rolled back
  behind deletion before restoring application access. Cryptographic erasure does
  not cover an attacker already holding plaintext or exported keys.
- **Delivered registry/outflow/oracle/balance alerts:** local tests check metric
  expiry, pause counters and receiver rendering, not live collectors or receiver
  acknowledgement. Provision collectors and run the acceptance drill in
  [monitoring](../../infra/monitoring/README.md) before claiming coverage.
