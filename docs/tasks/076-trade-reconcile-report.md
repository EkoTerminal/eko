Changed files and behavior:

- `apps/server/src/exec/trades.ts`: owner-scoped submitted/rejected/detail/history operations, transaction-hash uniqueness and serialized transitions, stable owner-bound pagination, raw public order projection and account-scoped lifecycle events. The existing execution worker calls v1 reconciliation; no second timer is installed. A transaction must match the retained sender, chain, target, calldata, value, reported hash and receipt block hash. Reverts, missing/invalid fills and mismatches never acquire estimated fill amounts. A provably decoded zero-delivery buy is preserved as an actual zero and still runs the post-fill check; zero is not mistaken for absent swap evidence. Confirmations use decoded raw strings, serialize across replicas and retain terminal evidence. Bought amounts get the post-fill sell replay; unavailable or mismatched replay evidence remains durable/retryable and does not count as a miss. A measured failed sell atomically commits the confirmed fill, evidence, trading stop, incident and pending Scoreboard/post-mortem handoff.
- `apps/server/src/exec/trade-evidence.ts`, `src/exec/trade-reconcile.ts`: persisted evidence schemas isolated from execution/HTTP imports, trusted reconciliation/replay backend interface and validated, account/tx/block/actual-amount-bound sell evidence. The concrete indexed single-hop v3 decoder checks the pool, swap direction, sender/recipient and calldata currencies/fee, measures net token transfers (including transfer tax), and measures native output from the router's WETH Withdrawal event with the unwrap recipient bound in calldata. Unrelated, missing, duplicate swap or wrong-direction logs refuse decoding. All quantities stay integer strings/bigints.
- `apps/server/src/exec/trade-backend.ts`: the 075 v3 acquisition backend can supply an accepted reconciliation backend. The production acquisition default remains unavailable; construction is not acceptance. Pons/v4 execution is not enabled.
- `apps/server/src/exec/service.ts`, `src/app.ts`: expose lifecycle operations through ExecutionService, attach incidents/account-scoped v1 orders events, and run v1 reconciliation under the existing worker's non-reentrant loop. Heritage paper/testnet/live reconciliation remains in place.
- `apps/server/src/http/v1/trade.ts`: POST `/v1/trade/order/:id/submitted` takes exactly `{txHash}` and returns `TradeOrder`; POST `/v1/trade/order/:id/rejected` takes exactly `{code: 'user_rejected' | 'signing_failed'}` and returns `TradeOrder`. GET `/v1/trade/orders` returns `{rows: TradeOrder[], cursor: string | null}` with optional UUID cursor and limit 1–100 (default 50); GET `/v1/trade/orders/:id` returns `TradeOrder`. Wallet sessions, exact mutation origins, demo refusals, strict parsing, bounded rates and private/no-store responses apply. Other owners receive 404 and cannot use another owner's cursor. Submission recording stays available when trading is paused so already signed transactions can be reconciled. A reported hash alone never confirms a fill.
- `apps/server/src/ws/hub.ts`: authenticated `orders` subscriptions and typed `{t:'ev', ch:'orders', kind:'order', data:TradeOrder}` events. Fanout and sequences are scoped to the account; anonymous subscription and generic public publication refuse orders.
- `apps/server/src/obs/incidents.ts`: transactional miss recording reuses the durable ops stop and audit incident shape, prepares a 24-hour post-mortem deadline, and queues the original quote, transaction bytes, receipt logs, decoded fill and sell evidence in a private pending record for 112.
