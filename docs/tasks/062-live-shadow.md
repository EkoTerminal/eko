# Task 062 · Frozen live shadow runner and report

Depends on 061. Implements [Guard 2.0](../guard/guard-2.0.md) §9.4. Start a frozen candidate shadow; seven days/5000 launches plus required follow-up are external elapsed-work signals.

## Do

1. Run with isolated shadow mode across API/policy/Signal without active influence, source/cost/coverage telemetry and v1/v2 disagreements.
2. Require both duration and launch count, then mature final entrants through their horizons/confirmation; checkpoint progressing job once.
3. Report actual covered duration/launches/maturity, budgets/latency/service-bot errors and gate regressions; prepare complete release manifest only when all applicable gates pass.

## Don't

Publish candidate badge active, stop at duration while last entrants immature or promise continuation after session without a running mechanism.

## Report

Changed files and source/candidate revision; exact focused check commands and exit codes; remaining gaps and reproduction steps. For acquisition/runs, include actual request units, pricing/cost, coverage and process/log/checkpoint with next action. Distinguish fixtures from measured validation and prepared work from released work.
